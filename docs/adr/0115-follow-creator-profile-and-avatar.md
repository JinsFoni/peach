# ADR-0115：发布账号的头像与站上资料进创作者档案

- 状态：已采纳（决策三的排布由 ADR-0116 改写，其余仍有效）
- 日期：2026-10-24
- 相关：ADR-0052（判据确定的结果直接落库）、ADR-0040（后继）、ADR-0053（存量补派与指纹）、
  ADR-0069（页头只给五项）、ADR-0096（关注作者建档）、ADR-0098（创作者身份断言）、
  ADR-0067（女优资料行）、ADR-0114（同一个来源的播放）

## 背景

ADR-0096 让关注来源把作者建成本地实体：绑上 `<provider>@<ref>` 的 `creator`，作品按追更条目
进馆藏。资料页上这个实体只有一个名字和一个首字母——头像取图那条路对这类来源返回空
（`follow_assets.mirror_avatar_url` 只认 kemono／`official_links`），资料行一条也没有。

可她本人在站上公开着一整页：头像、一段自我介绍，和一张资料表（感情状态、取向、性别、
出身地、三围、身高、体重、种族、发色、胸部、纹身、穿环、兴趣、几句话的问答）。这些全在
她人物页的服务端 HTML 里，匿名一次请求就能拿到，不需要登录、不碰任何付费或受限内容。

ADR-0069 又明确过页头只给五项（生日、身材、出道、生涯、标签），理由是「一行放不下的东西
放进去只会把这五项挤成两行」。这两条并不冲突，但需要说清楚多出来的读数放哪里。

## 决策

1. **资料进 `performer_profile`，站上原文进 `raw`。** 账本那一行只有固定的那几列：
   `身高` 与 `三围` 换算成厘米进 `height_cm`／`bust_cm`／`waist_cm`／`hip_cm`（三围那一格写英寸
   时按 ×2.54，写 `cm` 时照收），`出身地` 进 `birthplace`，`兴趣爱好` 进 `hobbies`。
   体重、种族、发色、纹身、穿环、感情状态这些账本没有列，随 `raw["资料"]`
   （`[{label, value, glyph}]`）与 `raw["简介"]` 一起存。那一页上另有两处也按原文进同一列：
   头像右边那几格读数（`模特排名`、播放量、订阅者）进 `raw["读数"]`，她自己登记的账号进
   `raw["社交"]`（`[{label, url, glyph}]`）。不新增列。
2. **页面用语在采集那一侧定，展示那一侧不认识站点。** 标签译文、`是／否`→`有／无`、
   `假奶子 否`→`胸部 天然`、图标名，统一在 `pornhub_profiles.ABOUT_FIELDS` 里；表里还没
   收录的项照原文列。那两格自述问答（站上问「会勾起／浇灭我性欲的是」）不进资料表，列在
   `ABOUT_SKIPPED` 里：答的多是一句话，读数那一栏只列认人的项。`performer_header.about()` 只做
   形状校验与长度截断（一格值 120 字、简介 280 字），照原样下发。
3. **资料卡还是五项，站上资料单起一块。** 前端把它按 `auto-fill` 铺成几列，简介收在末尾，
   排布位置见 ADR-0116。右边那张资料表仍然是认人用的，十几项读数不挤它。
4. **头像用站上那一枚，装了就不再换。** 人物页 `#getAvatar` 是签名地址、只有 200×200 一档
   （换尺寸、去签名都回 401），装图走 `avatar_picker.install`，`source_kind` 记
   `official_profile`。发布账号没有本地作品可以截脸，这一档已经是最清楚的一版，所以不受
   「长边 ≥ 500」的自动补头像门槛约束；`installed_digest` 非空就整段跳过——人自己挑过的图
   尤其不能碰。
5. **一条实体一条后继，30 天一轮。** `creator-profile:<entity_id>`，取页在事务外，写库那一下
   走写账本通道。提交了保 30 天（体重、兴趣、简介都会变），一次都没取到只保 1 小时。
   资料行是别的来源（含人自己）写的就只补头像，不改资料——与 `write_profile` 自己的判据
   同一条。写入带批次号 `auto:creator-profile@<任务行 id>`，可按来源整批撤回。
6. **建档那一轮当场派，不等下一轮检查。** 关注检查结算时新作者还只是「待建档」的一组，
   实体由建档后继建出来，那边的声明看不见它们。建档后继把自己刚建出来的那几位交给
   `creator_profile_followup.declared_for`，挂在建档这一行下面派出去，链到第二层为止
   （`MAX_FOLLOWUP_DEPTH`）。一次检查里走的：追更检查 → 建档 → 补资料。
7. **只认能给出这一页的来源。** `PROVIDERS` 目前只有 `pornhub`：别的连接器只有作品列表，
   派出去就是一条注定取不到的失败。页型（`/model/`、`/pornstar/`、`/users/`）由来源地址
   决定，主机换成中文站，页签照来源自己的——三页给的节点是同一批。
8. **关注页那几个圆框读档案里这张图。** 来源自己那两档头像（社媒官方主页、归档站镜像）
   对只有作品列表的站在结构上就给不出，页面会一直停在首字母——而同一个人在建好的档案里
   早有脸。所以绑定了创作者实体、且这位装过头像的来源，圆框直接取
   `/entity-image?kind=creator&id=…&thumb=1&v=…`；次序是实体图 → 社媒官方头像 → 归档镜像
   → 首字母，三档拆成三个字段下发，回落留给浏览器（`data-fallbacks`）。实体图排第一是因为
   它是资料页在用的那张脸，人换过头像后关注页不该还是旧的那张或另一张。

## 后果

- 新绑上的作者第一次关注检查之后就有头像、简介与资料表，不必人去头像边车挑图。
- 同一位创作者在关注页、艺人页的在线档与资料页上是同一张脸；没建过档或还没装图的作者
  仍然按来源那两档走，最后一档是首字母。
- 资料表随站点更新：30 天后重取一次，人改了体重、兴趣、简介，下一次检查就同步。
- 站上这几格是作者自己填的，不比别的来源更权威，也不冒充核实过的身份断言：它只是这条
  档案的「她这么说」。身份类结论仍走断言与复核（ADR-0098）。
- 200×200 的头像在 160px 的圆框里够用，放大到更大尺寸会糊；人在头像边车里换成图库里
  更清楚的一张时，这条后继不会再把它盖回去（`installed_digest` 非空即跳过）。

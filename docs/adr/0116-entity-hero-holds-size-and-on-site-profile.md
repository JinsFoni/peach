# ADR-0116：身材与站上资料都排在资料卡里

- 状态：已采纳
- 日期：2026-10-24
- 相关：ADR-0069（页头只给五项）、ADR-0115（站上资料进创作者档案）、ADR-0031（React + BoardUI）

## 背景

ADR-0115 把发布账号在站上的简介与资料表放到了资料卡下面，理由是那十几项读数塞进卡里会把卡撑得
比这一页的主角还高。宽屏下这个理由站不住：卡里名字与计数占不满那一列，右边空着近千像素，资料
却另起一块排在卡下面，同一个人的东西分成两处看。

身材那一行也悬在卡的最右边，和身份之间隔着一道竖线，人得横着扫过去才看得见她的体型。

## 决策

**一、身材跟名字、计数排在同一列。** 身高、三围、罩杯合成的那一格（`[data-entity-size]`）跟在
名字与计数下面，与资料表里那几行同一副脸：一格图标、一格取值，等宽数字。取不到就不画这一格。

右边那张资料表因此只剩生日、出道、生涯、标签四项。ADR-0069 的判据不作废：页头仍然只放认人用
的这几项，上限仍是五项，超出的读数照旧走站上资料那一块。

**二、站上资料进资料卡，占名字右边那一栏。** `[data-entity-about]` 是资料卡里的一格：宽屏下
与姓名、计数并排，一列三项往右铺，一格一个「图标 标签 值」，对齐判据仍按 ADR-0115 定下的标签
栏。列宽跟着内容走：每列先按那一列最长的一格撑开，余下的宽度均分，所以格与格之间始终是同一个
间距，读数长短差得远时也不会挤出参差的空当。女优页同时有资料表时，第三栏让给它，站上资料退到
第二行、从第二栏铺到卡右沿。内容区不到 900px 时它铺满一行，跟身份信息一起排到头像那一行下面，
隔一道横线，按行铺开。一格里的标签和值按顶对齐，不按基线：标签那格是 flex，基线落在第一个子项
也就是图标的底边上，值跟着过去就比标签低几像素，整行还被撑高；字号与行高处处相同，顶对齐必然
是同一条基线，值折成两行时标签也留在第一行。

站上资料与身份同处一行时，两栏一起在头像右边居中，三行读数与左边三行落在同一组基线上：名字齐
第一行读数，计数齐第二行，身材齐第三行。读数那块的顶上留 9px，两块才一样高、居中之后头一行对齐
——名字是 24px 的字装在 32px 的行盒里，基线在盒顶下面 24.5px，读数一行只有 22px、基线在 15.5px
处，差的就是这一段。行距取左边三行的基线间距（相邻两行相距 31.5px 与 31px），一行 22px 加 9.5px
跟上，第三行差半像素。标签那格里的图标脱流放在左边：留在流里整格的高度基准跟着图标的底边走，
两块就不是同一副行盒。

**三、简介单独占卡里的一行，排在头像下面。** `[data-entity-bio]` 是资料卡里独立的一格，宽屏下
从整行的左沿起、占三分之二张卡，长了自己往下折，卡跟着长高；女优页资料表另占一行时它再顺延
到下一行。读数那块只有一格一格的值，一段话挤在里面会把三行的行距带歪。内容区不到 900px 时它
铺满整行。

**四、宽屏的每一格点名排布。** 头像、身份、资料表、站上资料四格都用 `grid-area` 写在样式里，
不留给自动排布：跨栏那一格一旦交给自动排布，它会先占第一栏，头像和身份被挤到后面去。

## 后果

- 一个人是谁、什么体型、她自己写了什么，在同一张卡里并排读完，不必再往卡下面找：姓名与身材
  占左边那一栏，十几项读数在右边按三行铺开，卡的高度跟着前三行定，不再按读数条数长。
- 一列三项意味着同一行的那几格共用行高：读数都占一行时三行一样高；哪一格的值长到折行，
  整行跟着高，值不会挤在一起——列宽按内容定，长句那一列自己撑开，正是为了让折行尽量不发生。
- 左边三行与右边三行落在同一组基线上，一副表的样子：名字齐第一行读数，计数齐第二行，身材齐
  第三行。两栏一起在头像右边居中，卡的高度不变；右边三行里前两行正好落线，第三行差半像素。
- 简介另起一行，读数那三行的行距不被一段话带歪；它只占三分之二张卡，右边三分之一留白，一段话
  也就不会一路顶到卡的右沿。
- 内容区窄下来时卡会变高：一行一项，十几项读数就是十几行。窄屏本来就是单列，读数按列铺不开，
  这一段的高度无从压缩。
- 卡片高度重新成为要留意的量：站上资料长起来（某一格写了几百字）卡会跟着长，届时按 ADR-0115
  的截断（一格值 120 字、简介 280 字）收口，不再靠挪位置。
- 女优页同时有资料表与站上资料时，第三栏只到第一行为止，站上资料那一带从第二栏一直铺到卡右沿。

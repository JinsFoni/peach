# ADR-0120：追更片源起播就钉最高档，不按窗口大小封顶

- 状态：已采纳
- 日期：2026-10-25
- 相关：ADR-0119（母清单带全部档位、解析结果落盘复用）、ADR-0114（清单改写播放）、ADR-0016（远端媒体读取口径）

## 背景

ADR-0119 把来源的每一档都交给播放器，由 hls.js 按实测速率自适应，并保留播放器的两条默认：
码率按播放器尺寸封顶（`capLevelToPlayerSize`）、自动档有 720p 地板（`minAutoResolution`）。
在那套默认下，起播第一段常常先给低档再升档，小窗口里自适应最多到 720p，要 1080p 得每次
在清晰度面板里手点一次。

需求是「默认使用最高清晰度播放」。用户同时选定了两件事：慢网卡顿也钉在最高档，不接受播放
器自己降档；小窗口也放最高档，不接受按窗口大小封顶。

实测（本机 Chrome，`/follow/item/45`、`/follow/item/76` 这类条目）：两条默认叠加时，1280×800
页面里的小画框起播停在 720p，xHamster 的 2160p 档要手动点名才会来。

## 决策

1. **母清单一进引擎就钉最高档。** `v10-player` 在 `hlsManifestParsed` 之后按分辨率（宽、高取
   小者）挑出最高那一档，设成手动档；像素相同取靠后的一档，只有一个档位的片源不动。此后
   换不换档由观众决定，播放器不再插手。
2. **不按窗口大小封顶。** 交给媒体元素的片源带 `capRenditionToPlayerSize: false`，小窗口里
   照样放最高档；这条开关同时去掉自动档的 720p 地板，观众点「自动」时选档只取决于实测速率。
3. **面板勾的行跟着引擎走。** 清晰度面板从引擎的当前档读勾选项（手动档是具体档位，自动档
   是 -1），不再把「自动」当成默认。观众在面板里点过任何一档就不再被钉回最高档；「自动」
   仍在面板里，点了就交回 hls.js。

## 后果

- 起播就是最高档，拖动进度条也按最高档的分片取：慢网下表现为等缓冲，不表现为降档，这是
  需求里明确接受的取舍。
- 小窗口、手机竖屏与大字幕画面都用同一档，画面尺寸交给播放器缩放。
- 观众点过档位之后本次播放不再自动回到最高档；重新打开片源时回到最高档。
- 面板显示的是引擎真实在用的档位，`自动` 与各固定档的勾选状态与播放一致。
- 服务端的档位合并、`quality=` 点名换单档清单、解析结果落盘复用都保持不变（ADR-0119）；
  这条只改播放器拿到母清单之后的选档策略。
- 回归：`frontend/e2e/player-v10.test.ts` 用两档母清单（160×90 / 320×180）在 390×844 视口
  里起播，核对播到 180p、引擎不在自适应、面板勾的是 180p。

## 拒绝方案

- **只把小窗口的封顶去掉，保留自动档起播**：起播仍会先给低档，观众仍要等升档或手点，
  与「默认最高清晰度」不符。
- **钉住最高档同时保留网速降档**：降档与「钉住」互斥，观察到的降档正是需求要排除的行为。
- **在服务端只下发最高一档**：母清单只剩一条 `#EXT-X-STREAM-INF`，观众失去手动换档与
  「自动」两项能力，也回到 ADR-0119 之前起播慢的状态。
